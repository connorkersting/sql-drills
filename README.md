# sql-drills

Daily SQL drills for Amazon BIE and analytics data science interviews, fall 2026.

A session is one problem at a time: 15 minutes of real attempt before any hint. Syntax and
function names get looked up at any time; approach never. Hints only come after the timer,
a full solution only after I've pasted my own attempt, and anything I miss gets a pattern
card at the moment of the error. One commit per problem. The first problem of a pattern
I have never attempted gets a 5-minute worked example on a toy schema first; every other
rule applies unchanged after it.

The problem is solved in DuckDB, not in LeetCode's editor. DuckDB is the bar. LeetCode
supplies the problem statement and, from 2026-08-26, a single confirming submit once
DuckDB accepts the query. Submit once, then save the query body, log the row, and commit,
all before the next problem starts. See CLAUDE.md for the full per-problem loop.

Every attempt is a row in log.csv, carrying a state of solved, shown, attempted-not-run,
or queued. Pattern cards and their review dates are in patterns.md. Problem files live in
problems/, generated by get.ps1; 000-template.sql is the matching header block for a
hand-written one.

reference.md is the syntax and environment sheet: function names, operators, grammar,
DuckDB mechanics, and the DuckDB/MySQL divergences that matter now that LeetCode is a
second oracle. It carries only what the rules hand over free at any time, and stops short
of any pattern not yet attempted. Skeletons stay in patterns.md and are not duplicated.

Run `.\get.ps1 <leetcode-slug>` to pull a problem into problems/ as a numbered drill file
plus a setup file of sample rows, then load that into DuckDB with the command it prints.
